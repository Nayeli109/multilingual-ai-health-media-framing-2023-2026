4. V4 ARCHITECTURES
======================================================================

Shared dimensions:

document representation:
z in R^768

frozen context prototype:
e in R^768

context-availability mask:
m in {0,1}

bottleneck / interaction rank:
r = 32

All normalization below is parameter-free LayerNorm.

No new attention mechanism, retrieval operation, neighbor weighting,
top-k selection, threshold, or context source is introduced.


----------------------------------------------------------------------
4.1 V4_FILM_R32
----------------------------------------------------------------------

Architecture:
Feature-wise Linear Modulation.

Define:

e_n = LayerNorm_no_affine(e)

h = GELU(W_e e_n + b_e)

where:

W_e : R^768 -> R^32

Then:

gamma = W_gamma h + b_gamma
beta  = W_beta  h + b_beta

where:

W_gamma : R^32 -> R^768
W_beta  : R^32 -> R^768

Fusion:

z_fused =
    z * (1 + m * tanh(gamma))
    + m * beta

Therefore:

if m = 0:

z_fused = z

exactly.

Approximate additional trainable parameters:

W_e + b_e:
24,608

W_gamma + b_gamma:
25,344

W_beta + b_beta:
25,344

Total:
75,296 trainable fusion parameters.

No additional learned scalar gate is permitted.


----------------------------------------------------------------------
4.2 V4_LR_BILINEAR_R32
----------------------------------------------------------------------

Architecture:
Low-rank multiplicative bilinear fusion.

Define:

z_n = LayerNorm_no_affine(z)
e_n = LayerNorm_no_affine(e)

u = U_z z_n + b_z
v = U_e e_n + b_e

where:

U_z : R^768 -> R^32
U_e : R^768 -> R^32

Low-rank multiplicative interaction:

q = u * v

where * is element-wise multiplication.

Project back to document space:

delta = W_o q + b_o

where:

W_o : R^32 -> R^768

Fusion:

z_fused = z + m * delta

Therefore:

if m = 0:

z_fused = z

exactly.

Approximate additional trainable parameters:

U_z + b_z:
24,608

U_e + b_e:
24,608

W_o + b_o:
25,344

Total:
74,560 trainable fusion parameters.

No additional learned scalar gate is permitted.


----------------------------------------------------------------------
4.3 CAPACITY CONTROL
----------------------------------------------------------------------

75,296

74,560

Relative difference:

======================================================================
10. CONFIRMATORY V4 INFERENCE
======================================================================

Two confirmatory hypothesis families are pre-specified.


----------------------------------------------------------------------
10.1 INCREMENTAL-CONTEXT FAMILY
----------------------------------------------------------------------

For each V4 architecture and each task:

VERIFIED_CONTEXT
minus
STAGE_A_NO_EVENT

Number of tests:

2 architectures x 3 tasks = 6.

All six randomization p-values belong to ONE Benjamini-Hochberg
family.

Therefore BH correction is performed across six tests, not separately
per architecture.


----------------------------------------------------------------------
10.2 CONTEXT-SPECIFICITY FAMILY
----------------------------------------------------------------------

For each V4 architecture and each task:

VERIFIED_CONTEXT
minus
the same architecture's PERMUTED_CONTEXT arm.

Number of tests:

2 architectures x 3 tasks = 6.

All six randomization p-values belong to ONE separate
Benjamini-Hochberg family.


======================================================================
11. INFERENTIAL PROCEDURE
======================================================================

Primary metric:
five-seed probability-ensemble OOF Macro-F1.

For every contrast:

- paired by article,
- exactly 199 articles,
- full class set,
- delta = Macro-F1(system A) - Macro-F1(system B).

Paired stratified bootstrap:

10,000 replicates.

Sampling is stratified by gold label.

The same sampled article indices are applied to both systems.

95 percent percentile interval:

quantile 0.025
quantile 0.975

No BCa interval.
No studentization.

Paired probability-vector randomization:

10,000 replicates.

For every replicate and article:

swap the entire class-probability vector between systems with
probability 0.5.

Two-sided p-value:

p =
(1 + number of null absolute deltas >= observed absolute delta)
/
(10,000 + 1)

No threshold tuning.
No calibration.
No clipping.
No probability renormalization.

14. FINAL ARCHITECTURE SELECTION RULE
======================================================================

Default final architecture:

STAGE_A_NO_EVENT.

A V4 context-aware architecture becomes ELIGIBLE to replace Stage A
only if, for at least one SAME task, BOTH of the following are true:

A) INCREMENTAL BENEFIT

VERIFIED_CONTEXT minus STAGE_A_NO_EVENT:

delta Macro-F1 > 0

AND

BH-adjusted q < 0.05
within the six-test INCREMENTAL-CONTEXT family.

AND

B) CONTEXT SPECIFICITY

VERIFIED_CONTEXT minus its own PERMUTED_CONTEXT:

delta Macro-F1 > 0

AND

BH-adjusted q < 0.05
within the six-test CONTEXT-SPECIFICITY family.

Both conditions must occur for the SAME task.

A positive bootstrap interval alone does not satisfy this rule.

A nominal uncorrected p-value alone does not satisfy this rule.


----------------------------------------------------------------------
14.1 IF ZERO V4 ARCHITECTURES ARE ELIGIBLE
----------------------------------------------------------------------

Final architecture:

STAGE_A_NO_EVENT.


----------------------------------------------------------------------
14.2 IF EXACTLY ONE V4 ARCHITECTURE IS ELIGIBLE
----------------------------------------------------------------------

That architecture becomes the final architecture.


----------------------------------------------------------------------
14.3 IF BOTH V4 ARCHITECTURES ARE ELIGIBLE
----------------------------------------------------------------------

Compute the equal-weight mean of VERIFIED_CONTEXT Macro-F1 across:

primary_frame
stance
misinformation_relation

for each eligible architecture.

Select the architecture with the larger three-task mean.

If the means are exactly equal to 12 decimal places:

fixed tie-break priority:

1. V4_FILM_R32
2. V4_LR_BILINEAR_R32


======================================================================
15. INTERPRETATION RULE
======================================================================

If neither V4 operator satisfies the eligibility rule:

the developmental evidence will support the conclusion that the
failure to establish context-specific gain is not confined to the
original Stage-B gated residual operator under the tested fusion
family.

This will NOT be interpreted as proof that event context contains no
signal.

It will be interpreted as failure to demonstrate a robust,
architecture-sensitive context-specific benefit under the tested
developmental conditions.

If a V4 architecture satisfies both confirmatory conditions:

the result will support the narrower conclusion that useful
context-specific signal can be extracted under at least one alternative
pre-specified fusion operator.

No causal claim about the underlying mechanism is permitted.
