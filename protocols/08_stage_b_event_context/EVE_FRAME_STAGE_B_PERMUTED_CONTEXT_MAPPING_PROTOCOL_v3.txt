MAPPING RULE

For each target task and outer fold independently:

INNER_TRAIN
- consider only context-available INNER_TRAIN documents;
- sort legacy_doc_id lexicographically;
- assign each document the next document's prototype in a cyclic
  one-position rotation;
- therefore no fixed point is permitted.

INNER_DEV
- context availability remains unchanged;
- each context-available INNER_DEV document receives one prototype
  from the INNER_TRAIN context-available pool;
- source index is:
  SHA256(task|fold|inner_dev|doc_id) mod pool_size;
- no INNER_DEV prototype enters INNER_TRAIN.

OUTER_TRAIN
- consider context-available OUTER_TRAIN documents;
- sort legacy_doc_id lexicographically;
- assign prototypes by the same one-position cyclic derangement.

OUTER_TEST
- context availability remains unchanged;
- each context-available OUTER_TEST document receives one prototype
  from the OUTER_TRAIN context-available pool;
- source index is:
  SHA256(task|fold|outer_test|doc_id) mod pool_size;
- no OUTER_TEST prototype enters OUTER_TRAIN.

NO_CONTEXT
- remains context_available = 0;
- receives no prototype;
- receives no fallback.

The mapping is independent of model seed.
Therefore all five training seeds use exactly the same control mapping
for a given task/fold/phase.

No primary-frame, stance, misinformation-relation, topic, language,
country, region, source, or EventGold information is used.
