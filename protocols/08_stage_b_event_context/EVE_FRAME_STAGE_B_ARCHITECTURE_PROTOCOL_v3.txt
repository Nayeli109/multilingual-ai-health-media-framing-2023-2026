==================================================
6. EVENT PROTOTYPE
==================================================

For a target article with >=1 verified event neighbor:

e_i =
uniform arithmetic mean of the frozen XLM-R context representations
of all verified neighbors.

Every verified neighbor receives equal weight.

Frozen verifier probability is NOT used as an aggregation weight.

No top-k truncation is used.

No learned attention over neighbors is used.

For an article with zero verified neighbors:

context_available m_i = 0.

No artificial event prototype is constructed.

==================================================
7. VERIFIED_CONTEXT FUSION
==================================================

Let:

z_i =
trainable Stage-A-style XLM-R document representation.

e_i =
frozen event prototype.

m_i =
1 if verified context exists;
0 otherwise.

Context projection:

c_i =
m_i * LayerNorm(
    W_c e_i + b_c
)

W_c:
768 x 768 trainable linear projection.

The projection is shared across all three tasks.

Context gate:

g_i =
m_i * sigmoid(
    w_g^T [z_i ; c_i] + b_g
)

The gate is a scalar.

The gate is shared across all three tasks.

Fused representation:

z_tilde_i =
z_i + g_i * c_i

The existing Stage-A dropout and task heads operate on z_tilde_i.

Exact NO_CONTEXT invariant:

if m_i = 0:

c_i = 0
g_i = 0
z_tilde_i = z_i

Therefore no learned substitute vector is supplied to an article with
no verified event context.

==================================================
8. NEGATIVE CONTROL: PERMUTED_CONTEXT
==================================================

A parameter-matched negative control is predeclared.

PERMUTED_CONTEXT uses:
- the same main encoder;
- the same frozen context encoder;
- the same context projection;
- the same gate;
- the same heads;
- the same optimizer;
- the same folds;
- the same seeds;
- the same context-availability mask m_i.

Only context identity is disrupted.

No main-task label is used in constructing the permutation.

To prevent held-out article information from entering training through
the control:

INNER-SELECTION PHASE

For context-available INNER_TRAIN documents:
verified event prototypes are deterministically deranged among
INNER_TRAIN context-available documents.

For context-available INNER_DEV documents:
false context prototypes are deterministically assigned from the
INNER_TRAIN prototype pool.

No INNER_DEV-derived prototype is supplied to INNER_TRAIN.

OUTER_REFIT / TEST PHASE

For context-available OUTER_TRAIN documents:
verified prototypes are deterministically deranged among
OUTER_TRAIN context-available documents.

For context-available OUTER_TEST documents:
false prototypes are deterministically assigned from the
OUTER_TRAIN prototype pool.

No OUTER_TEST-derived prototype is supplied to OUTER_TRAIN.

If a training prototype pool contains only one context-available
prototype, that prototype may be assigned to held-out control examples,
but no held-out prototype may enter training.

Permutation/assignment rules must be deterministic and frozen before
Stage-B supervised training.

The same control mapping is used across all five random training seeds
for a given task/fold/phase.

==================================================
12. PRIMARY STAGE-B COMPARISON
==================================================

Primary scientific comparison:

VERIFIED_CONTEXT
versus
frozen STAGE_A_NO_EVENT.

For each of the three tasks:

- construct five-seed probability-ensemble OOF predictions;
- average probabilities across seeds;
- take argmax only after probability averaging.

Primary metric:
Macro-F1.

Inferential unit:
article.

Seeds are stochastic fits, not independent observations.

Uncertainty:
10,000 paired stratified bootstrap replicates by true-label strata.

Primary hypothesis test:
10,000 paired article-level probability-vector randomization
replicates.

Multiplicity:
Benjamini-Hochberg correction across the three task-level Macro-F1
contrasts.

No fold-level or seed-level pseudo-replication is permitted.
